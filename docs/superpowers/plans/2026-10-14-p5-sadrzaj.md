# P5 — Proizvođači, O nama, Recepti, Analize, Postani partner: plan implementacije

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pet javnih stranica (domaćini, o nama, recepti, analize, postani partner) i tri admin ekrana koji ih pune.

**Architecture:** Tri nova entiteta (`Recept`+`ReceptSastojak`, `Analiza`, `PartnerPrijava`), svaki sa svojom migracijom, javnim upitima i admin CRUD-om po obrascu `Features/Utisci/Utisci.cs` iz P4. Katalog dobija filter `producer`. Frontend: klijentske stranice u `app/(shop)/`, admin ekrani po obrascu `app/admin/utisci`.

**Tech Stack:** ASP.NET Core 9, EF Core 9 + PostgreSQL, MediatR, FluentValidation, xUnit + SQLite in-memory; Next.js 15 App Router, TypeScript, Tailwind v4, TanStack Query, lucide-react.

**Spec:** `docs/superpowers/specs/2026-10-14-p5-sadrzaj-design.md`

## Global Constraints

- **Omotnica odgovora:** svaki endpoint vraća `{ data, error, meta }` preko `Envelope`/`EnvelopeList`/`EnvelopeCreated` iz `ApiControllerBase`. Nikad `Ok(dto)`.
- **Identifikator greške je DRUGI argument konstruktora:** `new DomainException("Poruka.", "kod_greske")`. `DomainException`→400, `NotFoundException`→404, `ConflictException`→409.
- **JSON izostavlja null** (`WhenWritingNull`): nullable polje je na žici odsutno. TS koristi `?:`, nikad `| null`.
- **`TestDb` dijeli jedan `DbContext`**; test koji tvrdi nešto o učitanim podacima zove `t.Db.ChangeTracker.Clear()`.
- **Testovi rade na SQLite** preko `EnsureCreated()` — migracije se u testovima ne izvršavaju.
- **`MediatR.Unit` i `Domain.Enums.Unit` se sudaraju** — alias ili puno ime.
- `dotnet ef` preko `AppDbContextFactory`: `--project src/EPiljara.Infrastructure --startup-project src/EPiljara.Infrastructure --configuration Release`. Ako živi API drži DLL-ove, i `dotnet test --configuration Release`.
- **Svaka migracija pravi samo tabele svog taska.** Ako `Up()` dira išta drugo, stani i javi.
- **Enumi u bazi kao string** (`HasConversion<string>().HasMaxLength(...)`), kao `Pretplata.Status`.
- **Ključevi grešaka validacije na žici su `input.<polje>`** (provjereno u P4 za `Utisci`: `OverridePropertyName` na pravilu nad izrazom radi). Svaki novi validator dobija test koji kroz `new ValidationException(errors).Errors.Keys` (ili kako to radi postojeći test u `UtisciTests.cs`) dokazuje ključeve koje forma čita.
- Srpski/ijekavica u porukama i tekstovima; identifikatori grešaka `snake_case`.
- **Analize se nikad ne seeduju** (spec O2). **Recepti se seeduju samo u demo seedu** (O3).
- **Kontrast WCAG AA** (4.5:1 za sitan tekst) za svaki novi par tekst/podloga; bijeli tekst na `sand` pada.
- **`useSearchParams()` mora biti u `<Suspense>`**; dinamičke rute (`[id]`, `[slug]`) čitaju parametar kroz `useParams()` kao postojeći `app/(shop)/korpice/[slug]/page.tsx`.
- `npm run build` **samo** u zadnjem tasku i **samo** sa ugašenim dev serverom.
- Ugrađeni Next mock (`frontend/src/server/mock`) se ne proširuje novim rutama (ruling iz P4); ako `tsc` traži novo polje na mock objektu, dodaj mu prazan/podrazumijevan podatak.
- Commit poruke završavaju praznim redom i `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Recept čiji je vezani proizvod u međuvremenu postao korpica, obrisan ili nedostupan** — javni detalj ne smije nuditi „Dodaj u korpu" za njega niti pući. Pokriveno u Tasku 4 (test) i Tasku 5 (UI grana).
2. **Update recepta sa manje sastojaka** — stari redovi moraju nestati, ne ostati siročad. Test u Tasku 4.
3. **Brisanje proizvođača koji ima analize** — 409 `producer_in_use`, ne 500 iz FK-a. Test u Tasku 7.
4. **Honeypot i ograničenje** — popunjeno skriveno polje ne upisuje ništa, a vraća isti odgovor kao uspjeh; forma pokazuje poruku za 429. Test u Tasku 9, UI u Tasku 10.
5. **Nepostojeći ili neobjavljen slug/id na javnoj stranici** — „nije pronađen" sa linkom nazad, ne beskonačan spinner. Taskovi 2, 5.

Pomoćne funkcije u istom fajlu:

```csharp
internal static class ReceptPravila
{
    /// <summary>Koraci se čuvaju kao jedan tekst; na žicu idu kao lista bez praznih redova.</summary>
    public static IReadOnlyList<string> Koraci(string tekst) =>
        tekst.Split('\n').Select(r => r.Trim()).Where(r => r.Length > 0).ToList();

    /// <summary>
    /// Javni recept nudi proizvod samo ako je običan i nije obrisan. Korpica u sastojku bi
    /// otvorila put do korpice mimo /korpice i roka; obrisan proizvod ne smije u korpu.
    /// (Obrisani ionako ne prolaze globalni filter — provjera je i ovdje radi jasnoće.)
    /// </summary>
    public static bool SmijeUPrikaz(Product? p) => p is { Vrsta: VrstaProizvoda.Obican, IsDeleted: false };
}
```

Javni detalj učitava `Sastojci` sa `ThenInclude(s => s.Product).ThenInclude(p => p.Category)` i `.Producer` (ProductDto ih traži — provjeri `ToDto()` za Product). **Pazi:** globalni filter `IsDeleted` na `Product` čini da obrisan proizvod u `Include` dođe kao `null` — to je željeno.

Slug: `Slug.From(naslov)`, pa petlja `-2`, `-3`… dok `!db.Recepti.Any(r => r.Slug == s)` — isto kao `UniqueSlugAsync` u `AdminProducts.cs` (pročitaj ga). Prazan slug iz naslova od samih simbola → `"recept"`.

Create/Update provjeravaju sve `ProductId` iz ulaza jednim upitom (`db.Products.Where(p => ids.Contains(p.Id)).Select(p => p.Id)`); nedostaje li ijedan → `new DomainException("Sastojak pokazuje na proizvod koji ne postoji.", "proizvod_ne_postoji")`.

Update: obriši postojeće sastojke recepta (`db.ReceptSastojci.RemoveRange(...)`) i dodaj nove sa `Redoslijed = indeks`; naslov se mijenja, slug ne.
